# SteamDirect 3.0

Windows 游戏网络助手，提供直连切换、Steam / CS2 网络诊断和自动游戏网络历史报告。

## 下载

[**下载 Windows x64 版 SteamDirect.exe**](https://github.com/xiong1915/SteamDirect/releases/latest/download/SteamDirect.exe)

[查看所有发布版本](https://github.com/xiong1915/SteamDirect/releases)

支持 Windows 10 / 11 x64，需要 .NET Framework 4.8。可写目录首次运行会生成高 DPI 配置并重启一次；只读安装目录使用当前用户数据目录的配置和独立 UI 域，不要求管理员权限。逐屏幕高 DPI 需要 Windows 10 1703 或更新版本。

## 功能

- 关闭 FlClash 及识别到的相关应用，检查本机代理状态后重启 Steam。
- 保存原代理设置，并在本地手动代理端口就绪后恢复。
- 分项检查本地网络、DNS、代理 / VPN、Steam 服务与游戏连接。
- 自动识别 Steam 游戏启动与退出，保存每局网络记录。
- 生成简明报告，说明异常线索、可能位置和处理建议。
- 每条记录提供详细统计、原始采样、异常时间线和 CSV 导出。
- 支持托盘、开机自启、夜间模式、自定义主题色和日志管理。
- 文件清理是独立手动操作：先扫描预览，再确认清理；直连流程不自动删除文件。
- Precision Dark 统一主题，按需按钮／导航／开关／选项卡／图表／进度动效；支持减少动画，游戏运行时暂停装饰动画。

## 使用

1. 启动程序，在设置中选择外观、托盘和日志保留天数。
2. 需要切换直连时，先退出游戏并保存其他应用正在编辑的内容，再执行概览页的一键操作。
3. 网络卡顿时打开“网络诊断”。游戏结束后，在“游戏记录”查看报告，点击记录后的“详细数据”查看采样。
4. 需要恢复代理时先打开原代理软件，等本地端口就绪，再点击“恢复原代理设置”。

直连流程仅请求已识别应用正常退出，并复核 PID、启动时间与可信路径；不会强制终止 ChatGPT、编辑器、FlClash 或其内核。托盘驻留、保存提示、未知身份或超时都会停止流程。FlClash 自定义安装目录可能需手动退出。Steam 启动及退出参数仅发送给通过系统签名、Valve 发布者和原始文件名验证的程序。

本机检查无法保证排除运营商透明代理或所有未知网络中间层。网络历史中的延迟、超时比例和抖动来自主动探测，不能当作游戏服务器的实际延迟或丢包率。报告按已有证据描述问题，证据不足时会明确说明。

## 本地数据

- 设置、代理恢复备份和游戏历史保存在 `%LOCALAPPDATA%\SteamDirect\`。
- 默认日志目录为 `%LOCALAPPDATA%\SteamDirect\Logs`，可在设置中输入其他绝对路径；不依赖 D 盘。旧的 D 盘日志不迁移、不删除。新日志使用 `SteamDirect-` 前缀，保留策略不删除旧版或其他程序的日志。
- 新代理恢复点由当前用户 DPAPI 保护。旧明文备份必须在恢复界面核验来源并明确确认迁移；保留的 `.legacy` 原件仍可能包含敏感信息，不要上传或分享。
- 临时清理仅针对 `%LOCALAPPDATA%\Temp\SteamDirect` 下超过 7 天的 `.tmp`、`.temp`、`.cache`，拒绝重解析路径、硬链接及预览后被替换的文件；没有符合条件的文件时显示 0 是正常结果。
- 游戏监控默认低频采样，高负载时降低频率；游戏运行时暂停报告计算和详细数据读取。

## 从源码构建

在 Windows x64 上，使用 PowerShell 在仓库目录执行：

```powershell
.\Build.ps1
```

程序输出到 `dist\SteamDirect.exe`。源码位于 `src`，使用 Windows 自带的 .NET Framework C# 编译器，无需安装第三方包。

当前 PR #1 是 3.0 集成分支；最新正式下载链接仍指向已发布版本，更新 PR 不自动合并或发布。

运行 `.\tests\Run.ps1` 执行隔离回归测试，`.\tests\Run-Visual.ps1` 执行离线界面／资源验收。所有测试使用合成数据，不运行直连流程或改变系统代理。审计与验收范围见 [AUDIT-3.0.md](AUDIT-3.0.md)。

## 自动发布

新版源码与更新后的 `src/app.manifest` 版本号推送到 `main` 后，GitHub Actions 自动构建 Windows 程序、创建发布版本、上传下载附件并校验文件。

首页下载链接始终指向最新正式版本。相同版本重复推送会保留已经发布的附件；失败的任务可从 Actions 页面重新运行。
